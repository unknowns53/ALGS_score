以下、**Codex にそのまま投げる用の指示書**としてまとめます。
目的は「ALGS Match Point制の終了試合数分布を、現実寄りの仮定でモンテカルロ推定するシミュレータ」を作ることです。

```text
ALGS Match Point Finals の終了試合数分布を推定する Python シミュレータを実装してください。

目的:
- Apex Legends Global Series, ALGS の Match Point 制 Finals をモンテカルロシミュレーションする。
- 各大会が何試合目で終了するかの確率分布を推定する。
- チーム戦力の傾斜、地域ごとの戦力拮抗度、リスポーンによる総キル増加、キルポイント消滅、キルポイント移転をモデルに含める。
- 特に APAC-N のように試合数が長くなりがちなリージョンを、単に「弱い」と扱うのではなく、「地域内の戦力拮抗」「勝ち切り能力」「Match Point 点灯後の圧力」「ロビーのカオス度」として分離して表現できるようにする。

固定ルール:
- 20 teams
- 1 team = 3 players
- Match Point threshold = 50 points
- A team becomes match-point eligible only if it starts a match with total score >= 50.
- If an eligible team wins the next match, the tournament ends immediately.
- A team that reaches 50 points and wins the same match does not win the tournament in that match.
- Placement points:
  1st: 12
  2nd: 9
  3rd: 7
  4th: 5
  5th: 4
  6th-7th: 3
  8th-10th: 2
  11th-15th: 1
  16th-20th: 0
- Kill points:
  1 scored kill = 1 point

Core simulation flow:
1. Initialize 20 teams.
2. Assign each team latent strengths.
3. Repeat matches until:
   - a match-point eligible team wins a match, or
   - max_matches is reached.
4. For each match:
   - Determine which teams are match-point eligible at match start.
   - Generate placement order.
   - Generate respawn count.
   - Generate death event count.
   - Generate scored kills, neutral deaths, lost kill points, transferred kills, and revived knocks.
   - Allocate scored kills to teams.
   - Compute match score = placement points + scored kills.
   - Add match score to cumulative score.
   - If match-start eligible team placed 1st, end tournament.

Important Match Point rule:
- Eligibility must be evaluated before the match.
- Do not allow a team to become eligible and win the tournament in the same match.
```

ここからがモデル部分です。

```text
Team latent strengths:

Each team should have separate but correlated latent variables:

- placement_skill:
  Ability to survive, rotate, and consistently place high.

- fight_skill:
  Ability to generate kill points.

- win_conversion:
  Ability to convert late-game position into 1st place.

- macro_consistency:
  Reduces match-to-match variance in placement.

- volatility:
  Increases match-to-match randomness.

Do not model team strength as a single scalar only.

Generate these strengths using a multivariate normal distribution, then transform to useful positive weights if needed.

Configurable parameters:
- strength_sigma:
  Overall inequality of the lobby.
  Larger value means stronger top teams and weaker bottom teams.
  Smaller value means more parity.

- placement_fight_correlation:
  Correlation between placement_skill and fight_skill.

- placement_win_correlation:
  Correlation between placement_skill and win_conversion.

- volatility_mean
- volatility_sigma
```

順位生成は、単純なランダムではなく Plackett-Luce 系にします。

```text
Placement model:

Use Plackett-Luce sampling without replacement.

For each match, compute a placement weight for each non-eliminated team:

placement_weight_i =
    exp(
        rank_beta * placement_skill_i
        + consistency_beta * macro_consistency_i
        + normal(0, match_noise_i)
    )

where:

match_noise_i should depend on team volatility:
    match_noise_i ~ Normal(0, base_match_noise * volatility_i)

Sample full placement order from 1st to 20th using these weights.

Optional:
- Add win_conversion boost specifically for 1st place.
- The 1st-place selection can use a modified weight:

win_weight_i =
    placement_weight_i * exp(win_beta * win_conversion_i)

This makes “placing well” and “actually winning the match” related but not identical.
```

キル生成は、リスポーン・消滅・移転を分けてください。

```text
Kill, respawn, and death accounting:

Separate the following concepts:

- respawned_players:
  Number of successfully respawned players in a match.

- champion_remaining_players:
  Number of living players on the champion team at match end.
  Usually 1 to 3.

- death_events:
  Total full player eliminations in the match.

- scored_kills:
  Kills that actually count toward team match score.

- neutral_deaths:
  Full eliminations that do not award team kill points.
  Examples: ring death, fall death, invalid/no attacker, etc.

- lost_kill_points:
  Potential kill points erased because the original knock owner became invalid before confirmation.

- transferred_kills:
  Kills originally created by one team's knock pressure but credited to another team.

- revived_knocks:
  Knockdowns that were revived and never became full death events.

Use this invariant:

death_events = 60 + respawned_players - champion_remaining_players

Use this score accounting invariant:

scored_kills + neutral_deaths + lost_kill_points = death_events

Do not count revived_knocks as death_events.

transferred_kills are part of scored_kills, not additional kills.
```

リスポーン数は固定値ではなく、試合ごとにばらつかせます。

```text
Respawn model:

Support two models:

1. Poisson:
   respawned_players ~ Poisson(respawn_mean)

2. Negative Binomial:
   respawned_players ~ NegativeBinomial(mean=respawn_mean, dispersion=respawn_dispersion)

Negative Binomial is preferred because Apex matches are overdispersed:
- some games are quiet
- some games are chaotic with many respawns and high total kills

Parameters:
- respawn_mean
- respawn_dispersion
- max_respawned_players optional safety cap

Recommended defaults:
- respawn_mean = 6
- respawn_dispersion = 4
```

キルポイント消滅と移転は、総キルを直接増やすのではなく、死亡イベントから差し引く形にします。

```text
Kill credit model:

Given death_events:

1. Sample neutral_deaths:
   neutral_deaths ~ Binomial(death_events, neutral_death_rate)

2. Sample lost_kill_points:
   lost_kill_points ~ Binomial(death_events - neutral_deaths, lost_kill_rate_effective)

3. Compute:
   scored_kills = death_events - neutral_deaths - lost_kill_points

4. Sample transferred_kills:
   transferred_kills ~ Binomial(scored_kills, transfer_kill_rate)

5. Sample revived_knocks separately:
   revived_knocks ~ NegativeBinomial or Poisson
   revived_knocks do not affect death_events or scored_kills.

Effective lost kill rate should optionally increase under chaotic conditions:

lost_kill_rate_effective =
    lost_kill_rate
    * chaos_multiplier
    * match_point_pressure_multiplier

Parameters:
- neutral_death_rate
- lost_kill_rate
- transfer_kill_rate
- knock_revive_rate
- revive_knock_mean
- mp_pressure_lost_kill_multiplier
- chaos_multiplier
```

キルのチーム配分は、fight_skill と順位の両方で重み付けします。

```text
Kill allocation:

Allocate scored_kills across teams using multinomial sampling.

For each team, compute kill weight:

kill_weight_i =
    exp(kill_beta * fight_skill_i)
    * placement_kill_factor(placement_i)
    * survival_factor(placement_i)
    * pressure_factor_i

placement_kill_factor should generally be higher for teams that place well,
but should not make low-placement high-fighting teams impossible.

Example placement_kill_factor:
- 1st: 1.35
- 2nd: 1.25
- 3rd: 1.20
- 4th-5th: 1.10
- 6th-10th: 1.00
- 11th-15th: 0.75
- 16th-20th: 0.45

Optional:
- Add an early-death penalty for bottom placements.
- Add a winner kill bonus.
- Add a high-fight low-placement archetype so aggressive teams can die early but still get kills.

transferred_kills:
- Should affect kill distribution.
- Implement as a redistribution process:
  Some kills that would have gone to the original pressure team are credited to another team.
- Track transferred_kills in telemetry.
- It is acceptable in the first version to model transferred_kills only as a summary statistic and not explicitly track source/destination teams.
```

APAC-Nっぽさを入れるため、地域プリセットを作ります。

```text
Regional profiles:

Implement regional profile presets.
The purpose is not to rank regions by absolute strength.
The purpose is to control within-region parity, chaos, and win conversion patterns.

Profiles:

1. Americas-like:
   - higher strength_sigma
   - high win_conversion for top teams
   - moderate chaos
   - stronger correlation between scoring and winning

2. EMEA-like:
   - moderate strength_sigma
   - structured placements
   - lower chaos
   - moderate-high placement consistency

3. APAC-N-like:
   - lower strength_sigma
   - high parity
   - higher lobby chaos
   - weaker correlation between total scoring and win conversion
   - optional match-point pressure penalty
   - higher chance that non-eligible teams win after many teams are eligible

4. APAC-S-like:
   - higher volatility
   - higher fight randomness
   - moderate-high chaos

Important:
- Do not interpret longer Match Point finals as lower absolute regional strength.
- Separate:
  1. within-region parity
  2. absolute team strength
  3. win conversion ability
  4. match-point pressure effects
  5. lobby chaos
```

Match Point点灯後の圧力も入れます。

```text
Match Point pressure:

Implement optional pressure effects for match-point eligible teams.

When a team is match-point eligible at match start:
- It may receive a pressure penalty to win_conversion.
- It may receive a higher lost_kill_rate due to harder fights, focus, or conservative play.
- It may receive lower fight aggression.

Parameters:
- mp_pressure_enabled
- mp_win_penalty
- mp_kill_penalty
- mp_lost_kill_multiplier

Example:
if team_i is eligible:
    win_weight_i *= exp(-mp_win_penalty)
    kill_weight_i *= exp(-mp_kill_penalty)

This should be configurable and can be turned off.
```

テストはかなり重要です。特に Match Point の「次試合から有効」はバグりやすいです。

```text
Tests:

Rule tests:
1. Placement points are assigned correctly.
2. Kill points are added correctly.
3. Match Point eligibility is evaluated only at match start.
4. A team that reaches 50 and wins the same match does not end the tournament.
5. A team that starts a match with >=50 and wins does end the tournament.
6. death_events invariant holds:
   death_events = 60 + respawned_players - champion_remaining_players
7. kill accounting invariant holds:
   scored_kills + neutral_deaths + lost_kill_points = death_events
8. revived_knocks do not affect death_events or scored_kills.

Sanity tests:
1. With all strengths equal, no starting points, low respawn, and no pressure,
   tournament ending distribution should roughly center around 9-10 matches.
   Do not assert exact values, only broad range.

2. Increasing strength_sigma should generally reduce expected tournament length,
   because top teams reach Match Point earlier and win more often.

3. Increasing respawn_mean should generally reduce expected tournament length,
   because more death events create more scored-kill opportunities.

4. Increasing lost_kill_rate should generally increase expected tournament length,
   because fewer scored kills slow down Match Point eligibility.

5. APAC-N-like profile should generally produce longer and more variable finals
   than an Americas-like profile under otherwise similar settings,
   due to parity, chaos, and weaker score-to-win conversion.
```

この指示書の肝は、**総キル数を直接いじらない**ことです。
現実寄せするなら、

**リスポーンで死亡イベント母数が増える**
**一部は中立死・キル消滅でスコア化しない**
**一部は第三者に移転する**
**その結果として scored_kills が決まる**

という順番にしておくのがきれいです。

また、APAC-Nの長期戦についても、モデル上は

**弱さ = 長期戦**

ではなく、

**地域内拮抗 + カオス + 点灯後の勝ち切り難度 + 得点力と優勝変換力のズレ = 長期戦**

として扱うのがかなりフェアです。
